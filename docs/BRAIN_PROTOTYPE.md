# 多模态大脑原型：当前交接入口

本文件和 `RAPID_PROTOTYPE_PLAN.md` 优先于早期 OCR 规则等待方案。当前开发重点是把真实视觉语言模型接进等待任务，并与持续导航协调；旧版录像和 ZIP 保留为比较证据。

## 用户应当看到的过程

胸前相机连续输入，小脑持续输出可走区域、固定障碍、行人/车辆和图像坐标路径。用户指定目的地后，核心返回候选并等待确认，再按地图路线提示转弯。用户临时提问时，大脑依据最新画面回答；用户要求等公交或叫号时，大脑持续观察目标，发现后发出带证据时间的提醒。危险导航提示可以打断普通播报，等待目标仍保留。取消或换目标以后，旧推理结果不能完成新任务。

输入是相机帧、连续 PCM、可选定位和朝向；输出是路径/区域事件、文字答复、TTS 请求和提示音指令。当前没有原生音频生成模型，文字交给系统 TTS，实际产生的 WAV 与时间戳会随演示保存。界面和传感器采集由团队前端负责。

## 已落地的责任分工

- `LocalBackend` 默认 `waiting_mode='brain'`。`WaitingBrain` 调用真实视觉语言模型，结合画面、未经栏目规则加工的 OCR、近期环境转写和最近三次观测。OCR 本身不触发等待完成。
- `StreamingCore` 的导航工作线程与多模态工作线程独立。二者通过带时间戳的事件和任务状态协作，大脑推理期间继续接收最新相机帧。
- 多模态输出保留观察说明、实际标识、事件含义和判断。任务层只检查完整标识、当前任务版本、结果年龄和是否已提醒，不替模型解释价格、柜台或车辆到达。
- 单帧视觉模型加有限历史实现持续观察；这不是原生全双工视频模型。正在进行的推理不积累无限 KV，下一次选最新帧，跳过中间堆积帧。
- `target_observed` 是过去证据中的目标提醒，不代表允许上车、过马路或沿旧路径前进。叫号证据最多保留 45 秒，车辆 30 秒；超过导航新鲜度的提醒明确报出证据年龄。当前 CPU 延迟仍需在目标硬件优化。

## 真实模型比较

比较过 MiniCPM-V 4.6 的语言 Q5/F16 与视觉 Q8/F16，以及 Qwen3.5 2B、4B 的实际本地推理。小模型出现过把窗口号当票号、把车身编号当线路、遗漏并排取餐屏和错误理解广播的情况。完整失败保存在 `outputs/stage2/brain/`，不能把拒绝提醒等同于识别正确。

当前候选是 Qwen3-VL-4B-Instruct Q4_K_M + Q8_0 视觉投影器。两份权重合计约 2.95 GB，不是运行峰值。官方 llama.cpp 固定提交 `b29c606e28a01b1bc8c1351026a0fa6e616bf6c4`；C ABI 使用 greedy 采样、6 个 CPU 线程并关闭额外的权重重排副本。Python 加载同一 DLL，不需要 Torch、CUDA 或外部模型 API。

当前 `goal-scene-v9` 由同一模型处理两种观测：有新环境转写时进行文字语义判断，否则依据相机画面与原始 OCR 判断。叫号编号、窗口角色和“尚未叫到”等否定含义由模型解释。环境分支仍是同一大脑，不由正则代替语义。历史保留最近三次实际观察，不无限累积视频 KV。单步视觉判断是默认路径；两步场景提取 agent 的失败作为比较保留。

Qwen3-VL 2B 在相同 22 项配对测试中出现 5 次误提醒，未用来换取较低内存。4B 视觉 F16 对照为 8/9 正例命中、13 个负例无误提醒，遗漏的是环境广播；v9 增加同模型的独立转写语义通道。最终 Q8、v9、线程参数下的结果以 [FINAL_VALIDATION.md](FINAL_VALIDATION.md) 为准；每次实验保留原始输出，不删除错误案例。

## 验证边界

当前 59 项核心测试覆盖任务版本、取消、抢占、导航并行和既有路线逻辑；控制流测试使用替身模型，不是多模态效果证明。真实照片配对与后续连续回放单独计数。配对照片属于已检查的开发素材，不声称是独立盲测或证明模型没在预训练见过。

原地面分割比较、固定实体区域、路线回放保留。地图路径来自真实高德请求，但展示中的 GPS 序列是模拟输入；本轮没有取得商业街景训练授权，也没有世界空间 AR 定位实证。单目图像路径不是米制地面轨迹。LiDAR、深度和 AR 位姿留有接口，未执行真实设备接入。

新大脑已在连续回放中重新测量整套运行内存，数值和余量见最终报告；旧 OCR 架构的 20 分钟结果只属于旧版本。资源报告同时记录进程 RSS 和 DirectML 分配；前端预留 2 GB 是假设。没有 Mac、Xcode 或 iPhone，Swift 语法检查不能写成编译通过，Windows 峰值不能写成 Apple 峰值。

## 给前端 agent

先读取本文件、`INTERFACE_SPEC.md` 和 `APPLE_INTEGRATION.md`，核对包清单；先运行桌面例子，再在 Mac 构建固定源码的 XCFramework 和 Swift Package。使用 `CoreModelFiles` 显式传入模型路径，接入 `PRTSCoreSession`。保留证据帧、时间戳、任务版本和播放反馈。不要把 Python 环境或 Windows DLL 打入 iOS App，也不要用空回调代替尚未验证的模型调用。

主要原理图是 `diagrams/05-brain-cerebellum.svg`（同时提供 PNG）。早期 `04-queue-evidence` 描述历史 OCR 比较方案，不是当前等待决策主链。

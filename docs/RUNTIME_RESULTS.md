# PRTS Core 第二阶段运行与压缩记录

本页是开发记录，整体 goal 未完成。GB 均为十进制。桌面工作集和图形内存用于筛选；没有 Apple 实际 footprint、发热或 App 内性能结果。

## 已运行的组合

| 组合 | 实际验证 | 资源与效果边界 |
|---|---|---|
| CPU：Mask2Former ONNX FP32、YOLO11n ONNX、RapidOCR、SenseVoice INT8、原生 MiniCPM Q4/F16 projector、系统 TTS | 连续 20 分钟 | 峰值工作集 5.842 GB，加 2 GB 预留 7.842 GB；地面约 7 秒，全部移动引导过时转等待 |
| 干净 CPU 环境 | 毕设公交连续帧、真实语音、上述全模型 | 未安装 Torch，实际 ORT CPU 推理；此次公交未确认，不能引用旧方案的成功替代 |
| DirectML FP32 | 14 个固定输入与 CPU FP32 类别完全一致 | 约 222 ms 分割；图形资源过高。首次内存统计重复计入其他适配器，原汇总作废 |
| DirectML FP16 v2 | 同样 14 个输入；完整组合 90 秒 | 分割中位约 166 ms；完整组合保守包络 6.406 GB，含 2 GB 预留 8.406 GB，当前预算仍未通过 |
| DirectML FP16 + Q5 + 有界正向 OCR | 90 秒预检；完整连续 20 分钟 | 预检含预留 7.914 GB；20 分钟含预留 **8,000,009,216 字节**，超出 8 GB 约 9 KB，几乎贴线且没有余量；不标为正式达标 |

90 秒不是 20 分钟稳定性验证。循环录像测试不等于真实行走、麦克风或物理播报测试。CPU 20 分钟采用显式 CPU provider 的研究环境；随后又在未安装 Torch 的干净 CPU 环境完成全链路短片。两者的安装环境不能混称。

最新 `dml-q5-20min/` 使用未安装 Torch 的 DirectML 环境，包含启动和循环输入共 1206 秒，没有记录到工作线程错误，1562 个场景事件、60 段语音识别、40 个答复。峰值工作集 3.769 GB，采样 RSS 3.752 GB；DXGI local 1.606 GB、nonlocal 0.641 GB。每时刻保守合计的峰值为 6.000009216 GB。输入在公告和公交录像间循环切换，注入导航控制，20 次等待中仅 1 次确认，**不能作为公交识别率或完整任务通过结果**。期间有短时 C++ 编译、数值校验等后台工作，延迟数据不作为独占机器性能基准。

实际同一公交连续片段 `bus-dml-v5/` 则完整处理 61/61 帧并确认 912，证据年龄 2.937 秒；其演示视频与 TTS 时间线已完整解码。两项测试证明的范围不同，分别保留。

## 浮点压缩与精度

FP16 候选由已经验证的 FP32 ONNX 转换，外部 RGB 输入及概率输出仍为 FP32。`onnxconverter-common 1.16.0` 默认转换遗留部分 Cast 类型不匹配，首个候选无法加载，保留失败日志。v2 将已声明 FP16 输出的 Cast 属性修正到一致类型，并通过 ONNX 完整类型检查及实际推理。

v2 文件大小 457,925,438 字节，SHA256 `e11af7a4b0463a144933ab5d6a94541fd53decb2b121205418bdaeede05e4a18`。

| 固定门槛 | v2 结果 |
|---|---:|
| 平均原始类别一致率至少 98% | 99.8854% |
| 最低可走区域 IoU 至少 95% | 99.9175% |
| 人工标签可走区域 IoU 下降最多 1 个百分点 | 最大下降 0.03875 个百分点 |

输入包括 6 个胸前样本和 8 帧有人工标签的头部相机样本；不能把 8 帧头部标签称为胸前真值。这只是压缩数值门槛，不能证明行走任务全部可靠。此前 INT8 的原始类别一致率约 95.68%，未通过既定门槛，未采用。

[ONNX Runtime 浮点转换文档](https://onnxruntime.ai/docs/performance/model-optimizations/float16.html) 提供混合精度转换路径；本项目对导出结果另做实际输入验证。

## 图形计量更正

机器的 DXGI 枚举返回三个不同 LUID、同名的 NVIDIA 适配器。实际单进程测试中，三个条目报告完全相同的用量。旧工具把它们累加，导致三倍计算。`adapter-audit-fp32.json` 保存了逐适配器记录；旧 `preflight-dml/` 数据保留，但其总量不再用于结论。

现在显式设置 DirectML `device_id=0`，只查询相同 DXGI 索引的当前进程 local/nonlocal usage。此索引对应关系见 [DirectML provider 文档](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html)。FP16 感知单独运行约 1.606 GB local、0.641 GB nonlocal；不能仅报告进程 RSS 而漏计图形分配。nonlocal 可能部分与 RSS 重叠，因此三项之和仍是保守包络，不是精确统一物理内存。

旧测量辅助 DLL 在进程退出时还有销毁顺序问题；改为进程生命周期持有 COM 引用后，新辅助工具与 90 秒完整测试均正常退出。该工具仅用于 Windows 测量，不是产品推理依赖。

## 语言权重量化

正确冻结的 `quantization-v2/` 同样使用 F16 projector、单图切片设置、4096 token 上下文和相同 C ABI。

| 语言部分 | 八个开发回归 | VLM 单独峰值工作集 |
|---|---:|---:|
| Q4_K_M | 7/8；纯文字 57B 只返回 B | 2.185 GB |
| Q5_K_M | 8/8，当前研究默认 | 2.015 GB |
| F16 | 8/8 | 2.953 GB |

五个车辆图像是 8、20、20A、SL3 及非线路车身编号，剩余三项是文字标识提取。该表不是泛化准确率。不同独立运行的工作集受内存驻留影响，不能因为 Q5 这次低于 Q4 就断言更高位宽普遍更省内存。当前完整开发回归已确认 8，但新照片 101X 漏报，见公交记录。

另构建预填充 microbatch=128 的原生候选，保持同一权重和图像切片；八项回归仍全部通过，单 VLM 峰值约 2.012 GB。该配置尚未通过完整组合长时间测试，未据此替换默认值 256。

microbatch=128 完整组合 90 秒包络 5.9068 GB，相比有界 OCR 基线 5.9138 GB 差约 7 MB，未提供所需余量。另一次关闭 OCR CPU arena 的 90 秒为 5.9146 GB，也没有明确节省；两者未作为默认优化采用。

视觉编码/投影的矩阵 Q8_0 候选由官方 F16 文件派生，仅量化支持 32 元素分块的 F16 二维权重；卷积、位置、归一化、偏置及不对齐矩阵保留原精度。文件为 726,599,744 字节，SHA256 `4167629ec2b826cc304f189a81bc0b1a7bf0476cb5e71844d27d46fd94158c30`。语言仍用 Q5，八项开发回归 8/8。完整组合 90 秒无记录到的线程错误，包络 5.5331 GB，含预留 7.5331 GB。证据在 `native-vlm/vision-q8-v1/` 和 `endurance/preflight-dml-vision-q8/`。

`endurance/dml-vision-q8-20min/` 已完成 1,200 秒输入、总运行 1,205.844 秒：1,572 个 scene、716 个 guidance、60 段转写、40 次问答，记录到的工作线程错误为 0。同步采样的 RSS + 所用适配器 local/nonlocal 最大值为 **5,586,100,224 字节**，加 2 GB 预留为 **7,586,100,224 字节**，距 8 GB 约 414 MB。前端预留尚未实测，nonlocal 可能与 RSS 重叠；这是桌面预算证据，不是 iPhone footprint。测试中循环播放既有片段，不能以提醒次数推算识别准确率。七个公交开发目标与 23 个干扰请求回归通过；四个保留案例与基线相同：101 成功、101X 仍漏报，16 个指定干扰请求无确认误报。Q8 可作为显式选择的桌面集成候选；通用接口仍保留 F16 默认。

旧 `quantization/` 的前三个图像取到了联系表，已在原目录写入 `INVALIDATED.md`。旧 6/8、7/8 汇总作废。重新取图后已人工检查原帧裁剪，不改写旧证据。

## 对集成团队的含义

已提供 CPU 可运行源码与原生模块，以及贯通模型、任务、地图和播报事件的 `PRTSCoreSession` 源码。Python 45 项回归已执行通过；Swift 只有语法树检查、没有编译。Apple OCR 和时序处理与研究参考有差别，具体见 [接入说明](APPLE_INTEGRATION.md)。当前不能称为已经完成 Apple App 验收。

不要在应用里同时引入两个不同版本的静态 ONNX Runtime；SenseVoice 的 sherpa-onnx Swift 包依赖的 ORT 版本与桌面实验版本不同，须在 Mac 上统一并复核。模型许可、实际平台能力和未完成项目在最终集成清单中单独说明。
